Taco · wrongly implemented

The scoreboard used a stale ruler

  • Runner docker image built ~Dec 2025 — but reports are dated 2026-07-01
  • Missing 6 months of committed scoring fixes: tag interpretation, hex whitespace normalization, the entire encode/roundtrip leg
  • Proof: zero roundTripHex fields in any published report — the current runner writes one on every pass
  • Cause: npm test runs docker compose up without --build. Library containers were rebuilt; the runner wasn't.
  • Bonus: README table (72.63%, #9) doesn't even match docker/reports (73.74%, #8)
Taco · wrongly implemented

~15% of vectors are unpassable

43 of 358 vectors pass for ZERO of 20 libraries; 9 more pass for exactly one.

  • Special floats expect null instead of the protocol's __cbor_float__ marker — JSON ate Infinity/NaN
  • float32-pi expects the double π for a float32 input
  • Truncated hex in 3 vectors; nachos's error message is byte-exact correct — and scored as failure
  • Two vectors demand accepting two-byte simple values <32 — RFC 8949 §3.3 forbids this. Nachos is penalized for being right.
  • Self-contradiction: the same invalid-UTF-8 hex is shouldSucceed:false in one file and shouldSucceed:true in another — every library forfeits ≥3 points no matter what it does
Taco · wrongly implemented

The ranking has a language bias

  • Byte-string map keys: python-cbor2 & rust-ciborium adapters emit bare hex (matches vectors); node adapters emit JSON.stringify wrappers (never matches)
  • → all CIP-25 / multi-asset vectors auto-fail for every JS library
  • python-cbor2's #1 rank (285) is partly an adapter artifact, not library quality
  • node-tiny-cbor: 314 of 358 failures are one typo (decodeFirstSync is not a function) — a bridge error ranked as library quality
  • Binary pass/fail hides all of this: no bridge_error / unsupported / mismatch taxonomy

Nachos · wrongly implemented

HIGH undefined corrupts to null


encode(undefined).hex      // "f7"    ✓ correct (0xf7 = undefined)
encode([undefined]).hex    // "81f6"  ✗ BUG — 0xf6 = null
// round-trip: [undefined] → [null]   silent data corruption
  • Top-level path uses encodeSimple (correct); the collection encoder has its own inline path that emits 0xf6 for both null and undefined
  • Fix: useCborCollectionEncoder.ts:87-90 — one line
  • Applies to arrays and map values
Nachos · wrongly implemented

HIGH CIP-25 parser can't read its own decoder


const decoded = decode(metadataHex);        // → Map instances
extractCip25FromCbor(decoded);              // → null  (always)
parseCip25Metadata(decoded);
// → { isValid:false, errors:["Missing CIP-25 label: 721"] }
  • Parser uses bracket access cborMetadata['721'] — but the decoder returns Maps, where that's always undefined
  • All 18 CIP-25 tests pass — because they feed plain object literals, never real decoder output
  • Consequence: the flagship feature of the new Cardano layer is non-functional in the real pipeline — and cbor.app was about to adopt it
Nachos · wrongly implemented

The codec disagrees with itself

  • MED Bignum: decoder produces BigInt > 2⁶⁴ from tags 2/3 — encoder throws on them. Decoded bignums can't round-trip.
  • MED Depth: decoder default maxDepth 100, encoder default 64 → nachos rejects re-encoding values it just decoded. This is the one real bug taco caught.
  • MED O(N²) residual: parseSequence re-hexes the buffer tail per item for arrays/maps/tags — the June fix covered only the source-map path
  • MED Cardano layer: pointer addresses classified as enterprise; Byron era detector fires confidence:'high' on any [0|1, x] array
  • LOW README documents options that don't exist (rejectDuplicateKeys on ParseOptions), wrong defaults, plain-object map examples (decoder returns Map)

The pattern behind everything

Green tests ≠ correct system

  • nachos CIP-25: 18 passing tests — fed object literals, never real Map decoder output
  • taco: 6 months of fixes marked “Done” in the plan — never in the deployed runner image
  • cbor.app: “100% coverage” — views excluded; one suite silently skipped
  • nachos codec: encoder and decoder each self-consistent — mutually asymmetric. Only caught by cross-testing (taco's roundtrip leg).

Does it all make sense?

Yes — the architecture is right.

Library → App → Cross-language harness is the correct three-tier design.
Nachos's base/Cardano split is right. cbor.app consuming nachos as a dependency is right. Taco's vector/bridge/container model is right.

What's broken is verification discipline, not design —
and after P0, re-measure: the ecosystem is far healthier than 73.74% suggests.
